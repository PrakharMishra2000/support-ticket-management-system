# STMS data model

H2 in-memory schema for STMS, running with PostgreSQL compatibility mode. Aligns with [requirements.md](requirements.md). JSON APIs use camelCase; columns are snake_case. Hibernate manages the schema with `ddl-auto=update`; Flyway migrations are not applied.

The JDBC URL uses `DB_CLOSE_DELAY=-1`, so the schema survives connection closure while the application is running. It is still volatile: all ticket and comment data is lost when the application JVM exits.

The H2 web console is enabled at `/h2-console`. Connect to `jdbc:h2:mem:ticketdb` with user `sa` and a blank password. This console is intended for local inspection only.

User directory tables are **out of scope**. `reporter_id`, `assignee_id`, and `author_id` are opaque positive integers supplied by the auth layer.

---

## Enumerations

Store enum names as portable `VARCHAR` columns. Java `@Enumerated(EnumType.STRING)` remains authoritative.

```sql
status   VARCHAR(32) CHECK (status IN ('OPEN', 'IN_PROGRESS', 'RESOLVED', 'CLOSED', 'CANCELLED'))
priority VARCHAR(16) CHECK (priority IN ('LOW', 'MEDIUM', 'HIGH', 'URGENT'))
```

Status transitions are **not** enforced in the database (no trigger required this revision). The service layer enforces [state-machine.md](state-machine.md).

## Table `tickets`

| Column | Type | Null | Default | Description |
|--------|------|------|---------|-------------|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | NO | identity | Primary key |
| `title` | `VARCHAR(200)` | NO | | Summary; 1–200 chars after trim |
| `description` | `VARCHAR(8000)` | NO | | Body; 1–8000 chars after trim |
| `status` | `VARCHAR(32)` | NO | `'OPEN'` | Create always `OPEN` |
| `priority` | `VARCHAR(16)` | NO | `'MEDIUM'` | |
| `category` | `VARCHAR(64)` | YES | `NULL` | Optional; letters, digits, space, hyphen, underscore |
| `assignee_id` | `BIGINT` | YES | `NULL` | Optional owner; JSON `assigneeId` |
| `reporter_id` | `BIGINT` | NO | | Set from `actorId` on insert; immutable |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | NO | `CURRENT_TIMESTAMP` | UTC |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | NO | `CURRENT_TIMESTAMP` | UTC; bump on every mutation |

Constraints:

- `PRIMARY KEY (id)`
- `CHECK (char_length(btrim(title)) BETWEEN 1 AND 200)`
- `CHECK (char_length(btrim(description)) BETWEEN 1 AND 8000)`
- `CHECK (category IS NULL OR category ~ '^[A-Za-z0-9 _-]{1,64}$')`
- `CHECK (assignee_id IS NULL OR assignee_id > 0)`
- `CHECK (reporter_id > 0)`

Indexes:

- `idx_tickets_status` on `(status)`
- `idx_tickets_priority` on `(priority)`
- `idx_tickets_assignee_id` on `(assignee_id)`
- `idx_tickets_reporter_id` on `(reporter_id)`
- `idx_tickets_created_at` on `(created_at DESC)`
- `idx_tickets_category` on `(lower(category))` (nullable)

Search (`q`): portable case-insensitive substring matching on `LOWER(title)` and `LOWER(description)`. No comment-body search this revision.

`updated_at` is maintained by the application (or a `BEFORE UPDATE` trigger that sets `updated_at = CURRENT_TIMESTAMP`). Comments do **not** update `tickets.updated_at` unless implementation chooses to; this revision does **not** require bumping the ticket timestamp on comment insert.

## Table `comments`

| Column | Type | Null | Default | Description |
|--------|------|------|---------|-------------|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | NO | identity | Primary key |
| `ticket_id` | `BIGINT` | NO | | Parent ticket |
| `body` | `VARCHAR(4000)` | NO | | 1–4000 chars after trim |
| `author_id` | `BIGINT` | NO | | Set from `actorId`; immutable |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | NO | `CURRENT_TIMESTAMP` | UTC; append-only (no `updated_at`) |

Constraints:

- `PRIMARY KEY (id)`
- `FOREIGN KEY (ticket_id) REFERENCES tickets (id)`
- `CHECK (char_length(btrim(body)) BETWEEN 1 AND 4000)`
- `CHECK (author_id > 0)`

Indexes:

- `idx_comments_ticket_id_created_at` on `(ticket_id, created_at ASC)`

On delete of a ticket: **not applicable** (ticket delete is out of scope). If delete is added later, comments must cascade or be blocked explicitly.

## Illustrative DDL

```sql
CREATE TABLE tickets (
  id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title         VARCHAR(200)  NOT NULL,
  description   VARCHAR(8000) NOT NULL,
  status        VARCHAR(32)   NOT NULL DEFAULT 'OPEN',
  priority      VARCHAR(16)   NOT NULL DEFAULT 'MEDIUM',
  category      VARCHAR(64),
  assignee_id   BIGINT,
  reporter_id   BIGINT        NOT NULL,
  created_at    TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT chk_tickets_status CHECK (
    status IN ('OPEN', 'IN_PROGRESS', 'RESOLVED', 'CLOSED', 'CANCELLED')
  ),
  CONSTRAINT chk_tickets_priority CHECK (
    priority IN ('LOW', 'MEDIUM', 'HIGH', 'URGENT')
  ),
  CONSTRAINT chk_tickets_title_len CHECK (char_length(trim(title)) BETWEEN 1 AND 200),
  CONSTRAINT chk_tickets_description_len CHECK (char_length(trim(description)) BETWEEN 1 AND 8000),
  CONSTRAINT chk_tickets_category CHECK (
    category IS NULL OR REGEXP_LIKE(category, '^[A-Za-z0-9 _-]{1,64}$')
  ),
  CONSTRAINT chk_tickets_assignee_id CHECK (assignee_id IS NULL OR assignee_id > 0),
  CONSTRAINT chk_tickets_reporter_id CHECK (reporter_id > 0)
);

CREATE TABLE comments (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  ticket_id   BIGINT        NOT NULL REFERENCES tickets (id),
  body        VARCHAR(4000) NOT NULL,
  author_id   BIGINT        NOT NULL,
  created_at  TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT chk_comments_body_len CHECK (char_length(trim(body)) BETWEEN 1 AND 4000),
  CONSTRAINT chk_comments_author_id CHECK (author_id > 0)
);
```
